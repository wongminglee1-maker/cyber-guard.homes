一、协议伪装机制：为什么选择 Trojan 与 TLS 1.3？

传统的代理协议（如早期的 Shadowsocks 原始流、未伪装的 VMess）由于缺乏标准的 TLS 握手特征，其特征熵值在现代深度包检测（DPI）算法面前极易被机器学习模型标记，从而导致端口被掐断或 IP 被封禁。

CyberGuard机场 选用的是行业公认抗封锁能力极强的 Trojan-GFW 协议标准：

  • 伪装成合法的 HTTPS 流量： Trojan 协议的设计哲学不是“对抗加密检测”，而是“彻底将自己伪装成互联网上最普遍的合法 HTTPS 网站流量”。它通过标准的 443 端口与知名 CA 机构签发的高可信证书进行通信。
  • Web 真实回落机制（Fallback）： 当外部探测器发送非法的探测请求时，CyberGuard 入口服务器会自动返回一个真实运行的常规合规静态网站，完全符合标准 Web 协议规范，使得主动探测机制彻底失效。
  • TLS 1.3 前向保密： 采用现代密码学标准的 TLS 1.3 协议套件，即使未来服务端的私钥意外泄露，攻击者也无法逆向解密过去已经发生过的历史流量，确保通信前向安全性（Forward Secrecy）。

二、防 DNS 泄漏与 WebRTC 穿透防护实战

很多用户即便挂上了代理，却发现海外风控系统依然能够准确识别出其所在的真实地理省市。其罪魁祸首往往是 DNS 泄漏 与 WebRTC 漏洞：

  1. DNS 泄漏的危害： 当您在浏览器中输入海外网址时，如果系统依然向本地宽带运营商的默认 DNS 服务器（如 114.114.114.114 或三大运营商局域 DNS）发起明文解析请求，不仅所有浏览过的域名记录会被本地网络完全记录，还会导致解析出的 CDN 节点为国内污染节点，造成连接失败。
  2. CyberGuard 解决方案： CyberGuard 提供的 clash节点 订阅中内置了纯净的 DoH（DNS over HTTPS）加密解析配置。所有境外域名的 DNS 请求均通过已加密的内网隧道在境外出口直接完成，彻底阻断了本地运营商的明文嗅探。
  3. WebRTC 真实 IP 泄露防护： 许多浏览器在进行 WebRTC 音视频通信时，会绕过系统代理直接暴露网卡的本地公网真实 IP。配合 CyberGuard 推荐的 Clash TUN 虚拟网卡接管模式，可以将 WebRTC 流量强制收敛进虚拟网卡中，彻底杜绝 IP 泄露。
